# 06_refactor_policy

## 1. 固定母版规则

1. 先证明问题，再重构。
2. 结构重构与行为变更分离提交。
3. 保持公共契约兼容。
4. 没有测试支撑的重构不允许进入主干。

## 2. 允许的低风险重构

- 将 `print()` 迁移为结构化日志。
- 补充类型注解。
- 拆分 `FireDetector` 中过长方法，但保持 `detect()` 输入输出不变。
- 将 `FireTracker` 抽取为独立文件（若 detector.py 行数过多）。

## 3. 高风险重构（需人工确认）

- 修改 `detect()` 输出 schema。
- 修改传感器融合算法或权重结构。
- 修改火灾等级判定逻辑。
- 修改灭火联动触发条件或安全开关位置。
- 引入新传感器类型。

## 4. 当前不建议的重构

- 不应在无测试基线前修改 FireTracker 跟踪逻辑或融合算法。
- 不需要引入 `config_adapter.py` — 配置为嵌套 dict 传递，detector 按路径读取，足够清晰。
- 不建议将 `zones` 和 `evacuation` 逻辑拆入独立模块 — 当前与 detector 主流程耦合度低，留在 plugin 层即可。
