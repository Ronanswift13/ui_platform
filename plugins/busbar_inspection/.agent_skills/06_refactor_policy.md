# 06_refactor_policy

## 1. 固定母版规则

1. 先证明问题，再重构。
2. 结构重构与行为变更分离提交。
3. 保持公共契约兼容。
4. 没有测试支撑的重构不允许进入主干。

## 2. 本项目差异规则（busbar_inspection）

### 2.1 允许的低风险重构

- 抽取配置映射层（不改算法语义）。
- 抽取原因码映射工具（不改业务判断）。
- 将 `print()` 迁移为结构化日志。
- 拆分超长函数但保持输入输出契约不变。

### 2.2 高风险重构（需人工确认）

- 变更 `infer/postprocess/healthcheck` 接口行为。
- 重写切片 remap/NMS 核心算法。
- 调整缺陷类别枚举及告警级别映射。
- 一次性改动超过 5 个生产文件。

## 3. 执行流程（强制）

1. 写明重构目标与不变量。
2. 新增或更新对应测试。
3. 先跑 `./scripts/run_targeted_tests.sh <module>`。
4. 再跑 `./scripts/run_regression_tests.sh`。
5. 在 `07_learning_log.md` 记录影响与预防动作。

## 4. 回滚触发条件

任一条件满足必须回滚到上一稳定点：

1. `quality_failed` 比例异常上升且无明确业务原因。
2. `bbox` 越界或 `confidence` 越域。
3. 告警级别映射与既有策略不一致。
4. 回归脚本失败。
